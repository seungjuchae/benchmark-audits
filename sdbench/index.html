SDBench

We audited Microsoft SDBench on synthetic case 0. Both doctor models we ran, GPT-5 and Astra max, passed with 4/5: each named the lymphoma (IVLBCL) but missed the associated HLH. We found eight issues in how the benchmark gets to that score: what the Gatekeeper reveals or makes up, how it handles grouped orders, and what the Judge checks. Open a finding to see how each setup we tested behaved. None shows incorrect work getting credit in a real run, so there is no P0 so far.

The Gatekeeper’s instructions pull in two directions

The prompt forbids diagnosis-identifying information beyond what is requested, and it also says to return an existing report verbatim. It does not define which ancillary tests belong to a biopsy order, so this is not a definite rule violation.

Gatekeeper prompt · v6_fixed
Prohibited disclosures – never reveal or imply: … any information beyond what is requested that identifies the diagnosis (e.g. "consistent with X" or "suggestive of X")
If the investigation already exists in the vignette → return its report verbatim.

Why this may affect evaluation

If only named tests should be returned, the GPT-5 run exceeded scope. If a biopsy order includes the pathology department’s follow-up panel, that scope and its cost must apply to every participant. As it stands, the same Gatekeeper gave one doctor the full panel unasked and gave the other only what it asked for. This is not a claim that the tests are clinically inappropriate.

Diagnostic findings arrived without a single order

The prompt says findings that may determine the diagnosis should only come from targeted tests, and that patient questions which would break this rule must be refused.

Gatekeeper prompt · v6_fixed
Only allow the disclosure of findings that may determine the diagnosis in targeted and specific tests (such as microbiology or viral cultures growing specific organisms, biopsies showing specific cell types, genetic tests revealing specific genetic mutation). Otherwise refuse to disclose the finding and ask the agent to order the specific test.
If answering would break the Pathognomonic safeguard → refuse with the standard template.

The prompt also allows chart lookups

Another rule lets the Gatekeeper answer from the chart when the answer is there. For earlier non-imaging investigations, the prompt allows details only if they are non-diagnostic. It does not say how broad a “what has been done” question may be, or which findings count as diagnosis-determining, so this is a suspected violation, not a confirmed one.

Gatekeeper prompt · v6_fixed
If the answer exists in the chart → quote it in clinical‑documentation style (no first‑person quotes).
Historic investigations (non‑imaging) – May be acknowledged by type + date; provide details only if documented and non‑diagnostic.

Why this may affect evaluation

Astra placed 7 test orders against GPT-5’s 36, but much of its information came from this one question, and several of its orders cover more than one test or specimen. Comparing order counts or test costs between the two runs would be misleading.

Benchmark and grading details

How SDBench is scored

For each case, SDBench runs three roles in a loop. The doctor model receives a short case summary that does not reveal the diagnosis and, turn by turn, orders tests, asks questions or commits to a diagnosis. The Gatekeeper answers each order from the case’s full text. When the case contains the result, it returns that; when it does not, its prompt tells it to generate a synthetic result, though in the GPT-5 run it sometimes answered “not reported” instead. When the doctor commits, a Judge scores the diagnosis against the ground truth on a 1–5 scale; 4–5 counts as correct.

The Gatekeeper and Judge are fixed by the configuration; only the doctor model is being evaluated. So whatever the Gatekeeper discloses feeds straight into the doctor’s score.

Reading is_synthetic

is_synthetic is a label the Gatekeeper model sets itself; it is not an independent check. false means the response was not marked as containing fabricated results. It does not certify accuracy, appropriate scope or real-patient provenance, and refusals carry false too. true means generated content is included, not necessarily that the whole response was generated. The source report is itself synthetic.

What this audit supports

This is not evidence that either doctor model assumed normal results without ordering tests. The models asked and ordered; the Gatekeeper supplied extra information or generated missing results. These logs alone cannot establish how much that affected the final diagnoses.

Both models named the core disease
Each named IVLBCL after the skin-pathology results arrived, and both lost a point for missing HLH. For GPT-5, the B-cell markers that establish the lineage came only through the unrequested panel; Astra ordered that panel itself.
No P0 so far
No real run showed incorrect work receiving credit. The false-explanation result comes from an answer we wrote.
The information-gathering process is not validated
The configured GPT-5 Gatekeeper added unrequested results, answered a broad question with diagnostic findings and generated missing results. With an Astra Gatekeeper, whether an order was answered depended on how it was grouped; the GPT-5 Gatekeeper refused none of the same 36 orders.
The Gatekeeper may influence evaluation
Establishing a causal effect on a final answer would need a separate experiment, such as rerunning with the extra information removed.
A token-saving motive cannot be established
The agent prompt sets no token objective, and the log records no per-test rationale: the harness never fills the reason field. We do not infer the models’ intent.

Conditions for a consistent comparison

  1. Define the returned findings and included follow-up panels for each test ID.
  2. Define what a patient question may return, and apply the targeted-test rule to it.
  3. Align the test components disclosed to the doctor with those included in costing.
  4. Return “unavailable” for missing results, or use reviewed, fixed values shared across participants.
  5. Record source-backed versus generated provenance for each test component, not only for the combined response.
